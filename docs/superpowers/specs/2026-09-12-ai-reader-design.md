# AI 阅读器 设计文档

日期:2026-09-12
状态:计划一、计划二均已实现

## 实现核对

本版已交付阅读器与 AI 对话层。实现过程中有以下与原设计的明确差异：

- 页码使用 epub.js 位置索引加一,不随字号变化;对话仍一律以 CFI 文字位置锚定。
- API 密钥通过操作系统加密存储,并与保存时的接口 origin 绑定;修改接口地址后必须重新填写密钥,这是为防止被篡改的渲染层诱导主进程外发密钥而增加的安全约束。
- 书库的「全书对话」目前能加载历史消息,但没有搜索框,也不会根据历史 CFI 自动跳回原文;现有只读阅读器接口无法在不造成可见跳页的情况下完成任意历史位置映射,因此暂不实现。

## 1. 产品是什么

一个 EPUB 阅读器桌面应用,右侧带 AI 对话侧边栏。对话的上下文自动跟随阅读位置:AI 始终知道你在读哪本书、读到哪一页、这一页写了什么。用户可以用鼠标划选页面上的句子,这些句子会随下一条消息一起发给 AI。

翻页即换话题——每一页有自己独立的对话,翻回去就能看到当时聊过的内容。

开源发布在 GitHub,提供 macOS 和 Windows 安装包。

## 2. 技术选型与理由

| 决策 | 选择 | 理由 |
|---|---|---|
| 应用形态 | Electron 桌面应用 | 自带 Chromium,macOS 和 Windows 分页结果完全一致。本产品把"当前页显示了哪些文字"原样喂给 AI,分页不一致会导致同一本书同一位置在两个平台上 AI 看到的内容不同 |
| 支持格式 | 仅 EPUB | 可重排格式,分页、划选、取当前页文本都最好实现。PDF 是固定版面,渲染管线完全不同,工作量约等于再做一遍 |
| 渲染引擎 | epub.js | 分页、CFI 文字锚点、高亮标注、双页并排全是现成 API,与核心需求一一对应。已知风险:项目维护不活跃。缓解措施见 §3 边界二 |
| LLM 接入 | OpenAI 兼容接口 | 用户自填接口地址 + API key + 模型名。一套代码通吃 OpenAI、DeepSeek、Kimi、智谱、本地 Ollama、OpenRouter |
| 代码签名 | 不签 | Apple 开发者账号 99 美元/年,Windows 证书 200–400 美元/年。开源项目绝大多数不签,README 写清楚绕过步骤即可 |

## 3. 架构

两个进程,按"谁碰敏感资源"划分职责。

### 主进程(Node 侧)

碰文件、数据库、网络、密钥。

| 模块 | 职责 | 对外接口 |
|---|---|---|
| `books` | 导入(复制文件到应用目录)、扫描指定文件夹、提取书名/作者/封面 | `import(paths)` `list()` `remove(id)` |
| `db` | SQLite 读写,承载所有对话与阅读进度 | 各表的增删改查 |
| `llm` | 调用 OpenAI 兼容接口、流式转发、错误分类 | `stream(messages, onChunk)` `abort()` |
| `secrets` | API key 用系统加密存储(Electron safeStorage) | `set(key)` `get()` |

### 渲染进程(界面侧)

只管绘制与交互。

| 模块 | 职责 | 对外接口 |
|---|---|---|
| `reader` | 封装 epub.js:开书、分页、翻页、双页模式、取当前页文本与位置 | `open` `next` `prev` `setSpread` `getVisible()` |
| `selection` | 划选高亮、点击取消、收集已选句子 | `getQuotes()` `clearAll()` |
| `context` | 按降级策略拼装上下文,超限裁剪 | `build(book, visible, quotes, history)` |
| `sidebar` | 历史折叠列表、当前对话区、流式渲染 | — |
| `library` | 书架网格、导入入口、对话管理页 | — |

### 两条硬边界

**边界一:API key 永不进入渲染进程。** 界面只发出"请把这组消息发出去"的指令,主进程负责取密钥、调接口、把文字块流回界面。即使界面层存在脚本注入漏洞,也拿不到密钥。

**边界二:`reader` 是唯一接触 epub.js 的模块。** 其他模块只消费它输出的纯数据(文本、位置标识、页码)。epub.js 维护不活跃,若后续撞上绕不过的缺陷,只需重写这一个模块即可换成 foliate-js 或自研方案。

**`context` 单独成模块的理由:** 它承载产品的核心逻辑——降级策略、目录裁剪、多轮历史淘汰。它不碰界面也不碰网络,纯数据进纯数据出,可以脱离应用单独测试。

## 4. 数据模型

### 表结构

```
books          id · 书名 · 作者 · 封面路径 · 文件路径 · 导入时间 · 上次读到的位置 · 上次打开时间
conversations  id · 所属书 · 起点位置 · 终点位置 · 合并终点(可空) · 章节名 · 开头摘要 · 创建时间
messages       id · 所属对话 · 角色(user/assistant) · 正文 · 引用句子列表 · 时间
settings       键值对:接口地址 · 模型名 · 系统提示词 · 上下文上限 · 字号 · 主题
```

API key 不进数据库,单独走系统加密存储。数据库文件被拷走也拿不到密钥。

### 对话锚定机制

页码是运行时按当前字号算出来的,不能作为存储锚点。用户改一次字号,全书分页重算,旧页码全部失效。

因此对话锚定到**文字位置**(EPUB 标准的 CFI),规则如下:

1. 存对话时,记录这一页的起点位置与终点位置。只要书文件不变,这个标识永远指向同一段文字。
2. 重新分页后,对每个旧对话判断:它的起点是否落在新的当前页范围内。落在范围内则显示。
3. 一页可能装下过去的多个对话,侧边栏按起点先后全部列出。
4. 一个旧对话若横跨新的两页,归到其起点所在的那一页。
5. 「合并下一页」时额外记录合并终点,会话管理中显示为 `47(+48)`。

### 对话管理页不显示页码

书未打开时没有分页,因而没有页码。对话管理位于书库界面,故列表显示**章节名 + 该页开头 20 字**:

```
☐  第三章 那个夏天 ·「他终于明白过来,原来那天…」    5 条  3天前
☐  第三章 那个夏天 ·「街角的灯还亮着,雨已经…」      2 条  3天前
☐  第五章 归途(+下一页) ·「车站空无一人…」          8 条  昨天
```

这比页码更易辨认——页码本就随字号变动,用户记不住。侧边栏内(书已打开、已分页)照常显示页码。

## 5. 界面

### 书库界面

- 封面网格,显示书名、作者、阅读进度
- 导入方式三选一并存:拖拽文件进窗口、点按钮选文件、指定文件夹自动扫描
- 导入时把 EPUB 复制一份到应用数据目录,源文件被删除或移动不影响阅读与历史对话
- 入口:对话管理页(全部对话列表,支持批量删除)、设置页

### 阅读界面

左侧正文,右侧对话侧边栏。

```
┌─ 侧边栏 ────────────────────┐
│ 《书名》                     │  ← 常驻标题
│ 全书对话 23 条 ▸             │  ← 点开弹完整列表,可搜索、可跳回原文
├─────────────────────────────┤
│ ▸ 第 12 页 · 3 条            │  ← 当前章节内有对话的页,默认折叠
│ ▸ 第 31 页 · 1 条            │     无对话的页不出现
│ ▸ 第 46 页 · 5 条            │
├─────────────────────────────┤
│ ● 第 47 页(当前)           │  ← 当前页永远展开在底部
│   ┌───────────────────────┐ │
│   │ 引用:「他终于明白…」  │ │  ← 已高亮的句子
│   └───────────────────────┘ │
│   [ 问点什么… ]   [+新对话]  │
└─────────────────────────────┘
```

侧边栏只列出**当前章节**的历史对话,避免长书拥挤。顶部「全书对话 N 条」点开弹出完整列表,可搜索、可跳回原文。

### 划选交互

1. 拖选文字,松开鼠标即高亮。不需要点任何确认按钮。
2. 点击已高亮的句子取消高亮。
3. 多句可同时高亮,发送消息时统一打包给 AI。
4. 消息发出后,页面高亮自动全部清除。句子已固化在那条消息的记录里。
5. 高亮是纯临时标记,不存盘,关书即消失。第一版不做永久划线笔记。

### 跨页合并

句子在本页末尾断开、下半句在下一页时:

1. 点「合并下一页」→ 页面缩放为双页并排显示
2. 两页内容都进入上下文,两页的句子都能划选
3. 会话管理中仍归类到合并前那一页,标记为 `47(+48)`
4. 用户一翻页,双页立刻收回,对话框清空,老对话折叠
5. 合并 47+48 后再按翻页,先收回单页并停在第 48 页,再按一次才到 49

此功能仅为方便跨页勾选句子,不是常驻的双页阅读模式。

## 6. 关键流程

### 6.1 发送消息

1. 收集页面上当前所有高亮句子
2. `context` 模块拼装完整上下文(见 6.2)
3. 经 IPC 交给主进程 → 取密钥 → 调接口 → 文字块流式返回
4. 界面逐字追加,Markdown 边出边渲染
5. 完成 → 存库 → 清除页面所有高亮
6. 中途点停止 → 已输出内容照常保留并存库
7. 出错 → 按原因分类显示 + 重试按钮

错误必须分类显示,因为解决办法完全不同:

| 情况 | 提示方向 |
|---|---|
| 401 / 403 | API key 无效或无权限 |
| 429 | 额度用尽或请求过于频繁 |
| 404 | 模型名或接口地址填错 |
| 网络失败 | 连不上服务器,检查地址与代理 |
| 5xx | 对方服务故障,稍后重试 |
| 超时 | 请求超时 |

### 6.2 上下文拼装与裁剪

**永不丢弃:** 系统提示词、书名、作者、当前章节名、当前页正文、本轮引用句子。

**降级策略:** 基础层是书名 + 作者 + 当前页正文。增强层是全书目录 + 当前章节名,两者**必须同时可读取**才一起加入;只能读到其中一项时两项都不加。

**裁剪顺序**(依次执行直到装得下):

1. 目录裁成局部——只保留当前章节前后各 5 条
2. 删除最早的一轮问答(一问一答成对删除)
3. 目录整个丢弃
4. 仍然超限 → 明确报错「当前页文字量超出模型上下文上限」,**不静默截断正文**

**上限**在设置中可改,默认 8000。长度采用估算而非精确计数——精确计数需为每个厂商装配不同分词器,不值得;估算保留 15% 余量,若仍超限由接口报错,走 6.1 的错误分类。

### 6.3 翻页

1. 清除所有高亮
2. 若处于双页合并态 → 先收回单页,停在合并的第二页
3. 当前对话有消息 → 存库并折叠进历史;**一条消息都没有 → 直接丢弃,不入库**
4. 底部换成空白的新对话区
5. 记录阅读进度

### 6.4 开启新对话

- 当前对话为空 → 不做任何事,不弹窗
- 当前对话有消息 → 弹窗询问「保留本页当前对话?」
  - 保留 → 存库并折叠,这一页从此拥有两个对话
  - 不保留 → 删除当前对话,清空重来

### 6.5 系统提示词

内置一套默认提示词(中文回答、不剧透后文、简洁)。设置页提供文本框可修改,带「恢复默认」按钮。全局一套,不按书区分。

## 7. 测试策略

重点放在能脱离界面单独验证的地方。

| 对象 | 方法 | 理由 |
|---|---|---|
| `context` 拼装 | 单元测试 | 降级策略(目录与章节名缺一就都不加)、四级裁剪顺序、边界情况。出错表现为"AI 答得莫名其妙",肉眼极难发现 |
| 对话归属判断 | 单元测试 | 给定新页范围与旧对话起点判断归属。改字号后对话错位是最难复现的缺陷 |
| 流式接收 | 假造数据流 | 逐字拼接、中途停止、断流、各类错误码分类 |
| 数据库层 | 内存数据库 | 增删改查、批量删除对话 |
| 开书渲染 | 真实 EPUB 冒烟测试 | 备几本古腾堡计划公版书作样本,验证中文书、带图书、多层目录书能正常打开分页 |
| 关键路径 | 端到端自动化 | 导入 → 开书 → 划选 → 提问(假 AI) → 翻页 → 翻回去看到历史 |

- electron-builder 产出 macOS .dmg(Intel 与 Apple 芯片各一份)+ Windows NSIS 安装版 .exe

## 9. 第一版边界

### 不做

PDF、MOBI、AZW3、TXT 格式;永久划线笔记;书签;全书搜索;查词翻译;云同步;界面多语言;自动更新。

自动更新特别说明:macOS 上未签名的应用自动更新无法安装,做了也无效,待签名后再议。

### 要做的阅读基本功能

目录跳转、字号调节、浅色/深色主题、记住上次读到哪。缺这些不能称为阅读器。
